# Grilling

The user's current instructions take precedence. Preserve existing authorization, scope, and prior decisions; this skill does not authorize additional publishing, deployment, spending, or messages.

Surface decisions that would materially change a plan before the user commits to it.

- Read the brief, relevant code, and known decisions first. Answer factual questions from evidence rather than asking the user to repeat available information.
- Ask one decision question at a time and wait for the answer. Include your recommended answer and the tradeoff behind it.
- Resolve dependencies in order. Prioritize expensive or hard-to-reverse assumptions before cosmetic choices.
- Follow the user's answers instead of running a fixed questionnaire. Do not reopen settled decisions unless new evidence changes them.
- Stop when material uncertainties are resolved, the user has enough to decide, or they ask to stop. Do not manufacture questions to make the interview exhaustive.

Default output is the discussion and a concise recap of decisions and remaining uncertainties. A request to grill a plan does not itself request implementation.

If the user also asks to record decisions, use their requested path or existing project documentation convention. Keep domain terms in a short glossary; record a decision note when a real tradeoff is hard to reverse or surprising without context. Do not create a mandatory new documentation hierarchy.
