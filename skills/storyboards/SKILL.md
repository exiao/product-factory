# Illustrated storyboards

## Generated media in this workflow

For visual exploration, use [generated media and storytelling](../design-mode/references/creative-exploration.md#generated-media-and-storytelling) to make the human situation and changed outcome visible through composition, recurring subjects, and purposeful transformations. Keep character, setting, and product references consistent between panels; show the transition rather than relying on captions to explain missing causality. If the storyboard will guide motion, identify the anchor states for video-direction. An explicitly ASCII/text-only storyboard stays text-only. A storyboard is a human decision surface, not automatic approval to generate the finished film.

## Still-image generation

For generated or edited still images, use [$image-generation-guide](../image-generation-guide/SKILL.md): Codex built-in image generation, verified files saved in the local project. This applies to reference sheets and intermediate assets as well as final images. Keep this skill's creative requirements; do not automatically use provider CLIs, external generation plugins, or remote rendering services. An explicit user request for another provider takes precedence.

For a product journey, start from one person and one situation. State the people problem and design question in plain language. Describe a functional, emotional, or social need before naming a solution. Reuse supplied research, label material claims with source IDs and confidence, and distinguish an imagined scenario from an observed customer story. A dogfood pass can support product-behavior claims, not customer sentiment. For an animation concept, start from the intended takeaway, opening hook, causal progression, and payoff; an abstract diagram or metaphor does not need an invented persona or product encounter.

Write captions and visible actions before drawing. For a product journey with no supplied structure, a useful six-panel arc is setting, trigger, old way, encounter with the feature, one meaningful action, and the changed situation. For animation, choose panels around the meaningful beats and anchor states, with approximate timing and transition notes for the caller. Follow the requested panel count or narrative instead of forcing six. Show how one action causes the next state; mark untested causal links. Keep recurring subjects, the goal, and relevant context consistent across alternatives; use a separate strip for a meaningful branch.

## Editable visual direction

Read [references/visual-style.md](references/visual-style.md) for editable style defaults. A user-selected style or reference takes priority, followed by the calling animation or product brief, then that profile. Keep medium, palette, texture, typography, framing, and panel layout separate from the story so they can be revised without rewriting the narrative. When no direction is supplied, choose a fitting treatment and state the choice; ask only if the unresolved style materially changes the result. Do not impose a notebook look or a three-by-two grid. [Notebook style](references/notebook-style.md) is an optional preset, used only when selected.

Keep captions short; specify exact labels and required screen text. Do not invent product features, tickers, numbers, or successful outcomes as factual evidence.

Produce illustrated boards by default, using the available image-generation capability and its instructions. Pass the panel specification, recurring subject details, and selected style in one coherent brief; reuse supplied references. For multiple options, render a separate board for each so its story and visual direction can be compared. ASCII or text-only boards are appropriate when explicitly requested or for internal planning; they do not replace the illustrated deliverable. Do not call old provider scripts or promise a specific model unavailable in the environment.

Inspect the image before delivery: panel count and order, consistent person, situation, and actions, legible labels, causality from action to response to next step/outcome, and adherence to the selected style. Show waiting, retry, failure, abandonment, or recovery when that state is part of the design question. A proposed successful outcome is valid when clearly labeled as intended, not observed. Match visual polish and caption certainty to the evidence: a polished drawing must not make a hypothetical outcome look observed. Correct material mistakes with a focused edit. If visual generation or inspection is unavailable, report that limitation; a prompt is not a completed comic.

When the storyboard is a research stimulus, pilot comprehension with someone who has not heard the intended story, when available: ask them to describe what happens in each panel before explaining the concept. Record confusing transitions, then separately probe the problem, intervention and claimed benefit. A coherent story can depict an unwanted solution; agreement with its narrative is not demand. A synthetic reader remains a simulation. Do not add participant testing to a simple illustration request.

Deliver the concise panel captions, chosen style settings, and actual illustrated board or file link. For product journeys, include the people problem and design question; for animation concepts, include timing, transition notes, and the intended takeaway. When the storyboard informs a product decision, add a compact decision note with evidence labels, the recommendation, a plausible alternative explanation, and what evidence would change it. Preserve supplied uncertainty labels; drawing a claim does not validate it. For a simple illustration, captions and the image are sufficient.
