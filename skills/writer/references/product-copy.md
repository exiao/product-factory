# Product copy guidance

Use this reference for landing pages, paywalls, onboarding, ads, and App Store copy. Inspect the live product and current source before making a promise. Reverify prices, limits, entitlements, URLs, dates, metrics, and compliance language at the time of use.

## Build the message

1. Name the reader and the one action the surface should support.
2. State the concrete moment the product helps with.
3. Name the paid or changed behavior precisely. “Unlimited deep research” is a different promise from alerts, reports, chat, or data sources.
4. Add proof the reader can inspect: a receipt, citation, screenshot, workflow step, or verified result.
5. End with one clear action and the product's required disclaimer.

## Compliance and fact check

Avoid return promises, guaranteed outcomes, and advice-like commands unless the user supplies current approval. For a paywall, verify the actual gate in code before describing what Pro unlocks. If the product fact cannot be verified, write around it or use `[NEEDS SOURCE]`.
