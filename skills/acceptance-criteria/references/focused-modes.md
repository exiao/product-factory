# Focused acceptance-criteria modes

Read this reference only for `acceptance-criteria sharpen`, `acceptance-criteria assess`, or `acceptance-criteria define`.

## Sharpen

Keep the criterion's stable ID and source. Annotate the ambiguity, then show a local before/after with starting condition, action, observable result, evidence, and status. Preserve agreed scope and thresholds; if the expected result materially changes, mark the revised criterion proposed until it is agreed. Label a proposed threshold instead of silently approving it.

## Assess

Use only the evidence supplied with the request or artifact. Map each observed result to the criterion and its verifier. Mark absent, inaccessible, or unobserved evidence as `untested` or `blocked`; do not infer a pass, invent a baseline, or manufacture an approved threshold. Distinguish evidence about a proxy metric from evidence of the promised outcome.

## Define

Start from the agreed outcome and define the smallest criteria that make done observable. Carry unknown population, unit, denominator, window, baseline, target, or data source as explicit unknowns. Mark thresholds as proposed unless the supplied agreement makes them approved. A local request gets a concise annotated result, not a full requirements artifact.
