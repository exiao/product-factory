# Set up the five-part workflow

Use this guide when the user asks to build or improve how their coding-agent coworkers operate. It sets up working practices; the separate [product workflow](product-workflow.md) develops a particular product initiative. Do not require all five setup steps before every task.

| Step | Callable skill | Result carried forward |
| --- | --- | --- |
| Give agents context | [gather-context](../../gather-context/SKILL.md) | Prioritized source map, brief, and explicit gaps. |
| Confirm understanding | [confirm-understanding](../../confirm-understanding/SKILL.md) | Task interpretation, accepted boundaries, criteria, and unresolved assumptions. |
| Build shareable skills | [build-skill](../../build-skill/SKILL.md) | Editable instructions capturing a real repeatable practice, with validation limits. |
| Delegate to coworkers | [delegate-work](../../delegate-work/SKILL.md) | Bounded assignment and an inspected result, or the exact pending worker boundary. |
| Build improvement loops | [improve-workflow](../../improve-workflow/SKILL.md) | Trace-grounded diagnosis and an evaluated keep/revert decision. |

Start at the user's requested step or the earliest material gap. Reuse existing briefs, decisions, skills, and worker results; do not fabricate a missing stage just to complete the table. A new project may begin with gathering context; a recurring failure may begin with inspection and improvement.

Ask questions together when answers could change the outcome. Continue independent authorized work while an essential decision is pending. A useful setup handoff links the source, scope, result, remaining uncertainty, and next action in the existing project record.

Use `$gather-context`, `$confirm-understanding`, `$build-skill`, `$delegate-work`, and `$improve-workflow` in skill-capable coding agents. Slash-command presentation depends on the runtime; these are skill names, not shell commands or a bundled command-line program.
