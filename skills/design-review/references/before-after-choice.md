# Choosing before/after evidence

Use real screenshots and repro evidence for a polished third-party site or any surface whose CSS and state cannot be reproduced faithfully. Describe fixes over the real evidence or hand them to an implementation task. A rebuilt “after” that looks different because the chrome, typography, data, or responsive behavior changed is misleading.

For an owned app or rough internal surface, an in-context comparison can show the current and proposed states. Use the same route, viewport, auth state, fixture data, and capture method. Keep the surrounding navigation, card, and page chrome, and label placeholders. A static mockup proves a design direction, not a shipped fix.
