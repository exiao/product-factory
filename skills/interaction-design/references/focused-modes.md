# Focused interaction-design modes

Read this reference only for `interaction-design inspect`, `interaction-design critique`, or `interaction-design audit`.

## Review lenses

| Mode | Inspect | Evidence to label |
|---|---|---|
| Inspect | Steps, decisions, setup, waiting, coordination, and correction | Observed path, supplied report, or effort hypothesis |
| Critique | Labels, hierarchy, control scope, feedback, and the next state | Rendered behavior, supplied artifact, or findability hypothesis |
| Audit | Error, interruption, cancel, back, undo, retry, and persistence | Reproduced state, specified behavior, or untested recovery |

For a local review, annotate the affected control or transition; include a concise before/after proposal when it makes the local change easier to inspect. Preserve the existing task, platform conventions, and stable labels or IDs. Do not create a full wireflow or prototype for a narrow request. If the user asks to apply a named fix, change only the affected interaction and verify its direct path and recovery where relevant.
