# Research basis

Reviewed 2026-09-10. These are expert methods, not evidence that a particular product concept works. Read when choosing a representation or explaining the workflow; no need to reopen every source for each task.

- [NN/g: Wireflows](https://www.nngroup.com/articles/wireflows/), Page Laubheimer, 2016. Connect visible layouts through the control that triggers a change. Represent changed content and feedback within a screen, not just navigation. Use partial-screen views when repetition would hide the flow. This motivates the skill's wireflow deliverable.
- [NN/g: Mental Models](https://www.nngroup.com/articles/mental-models/), Megan Chan, 2024, reviewed September 2026. People predict system behavior from prior experience. This informs familiar vocabulary, explicit control and persistence, and preserving established interaction patterns unless the benefit warrants relearning.
- [GOV.UK: Making prototypes](https://www.gov.uk/service-manual/design/making-prototypes). Match prototype fidelity to the question. Interactive code supports realistic behavior testing; prototype implementation is not automatically suitable for production. This informs the distinction between a diagram, a functioning prototype, and production readiness. The GOV.UK toolkit and organizational mandates are not required here.
- [Design Council: Framework for Innovation](https://www.designcouncil.org.uk/resources/framework-for-innovation/). Explore possible responses to a defined problem, then test and refine promising ones. This informs structural alternatives only where the interaction remains open; it does not justify repeating accepted discovery or a fixed option quota.

The storyboard mapping, compact handoff, and routing to local skills are adaptations for this skill collection, rather than a prescribed framework from these sources.
